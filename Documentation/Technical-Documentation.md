# 技术文档

## 系统架构

本项目是离线优先的跨平台本地文件检索程序。Flutter/Dart 负责桌面界面、任务编排、文件级状态管理与查询结果展示；Python 本地服务负责文档、图像和音频处理以及模型推理；Chroma 负责本地向量存储与分页查询。所有运行期检索服务仅绑定本机回环地址，不依赖远程检索服务。

主要处理链路如下：

1. 文件发现层按用户选择的路径枚举文件，并保留无法解析内容的文件名记录。
2. 解析层读取原生文字、提取文字、图像信息、音频信息和摘要信息。
3. 嵌入层使用文本、图像和音频模型生成对应向量。
4. 索引层以一个文件对象为一个索引对象，只有该文件全部必要步骤成功后才提交更新。
5. 查询层解析用户文字或附件，在用户选择的路径及数据类型范围内匹配。
6. 存储层先按文件对象合并命中，再稳定分页返回；只有用户选择相关度排序时才完整计算并排序结果。
7. Flutter 界面展示文件名、完整路径、命中说明、总文件数和分页结果。

## 主要模块

- `lib/core`：文件类型、文件输入输出及共享基础能力。
- `lib/indexing`：文件发现、指纹、索引任务、失败记录、路径覆盖和数据库配置。
- `lib/embedding`：嵌入模型调用与向量结果。
- `lib/storage`：Chroma 客户端、文件对象事务和分页查询。
- `lib/query`：文字及附件查询、数据类型选择、摘要选择和后缀范围。
- `lib/retrieval`：关键词与向量混合检索。
- `lib/summary`：使用项目已有模型生成分层摘要。
- `lib/presentation`：文件库、查询、设置、弹窗和无障碍界面。
- `services`：Python 本地解析、模型、Chroma 与依赖管理服务。

## 内部接口

程序没有面向公网开放的 API。Flutter 只通过本机 HTTP 调用 Chroma 服务，通过受控子进程调用解析及模型服务。

核心接口包括：

- `MultimodalVectorStore`：文件级向量写入、替换、删除和查询。
- `PagedFileQueryStore`：统计匹配文件对象总数并按页读取。
- `SummaryGenerator`：为原生文字、提取文字、图像和音频生成摘要。
- `QueryAttachmentCoordinator`：解析查询文字和附件并组合查询单元。
- `IndexJobRunner`：运行可暂停、继续和停止的索引任务。
- `FileDiscoveryService`：跨平台枚举指定路径中的文件。
- Chroma 本地服务：健康检查、文件对象事务、分页查询和索引清理。

接口数据始终以文件对象为边界。同一文件中的文字、图像、音频及摘要可以形成多条内部向量记录，但统计和展示时只能形成一条文件结果。

## 维护要求

- 修改路径逻辑时必须同时检查 Windows、Linux 和 macOS 分支。
- 修改文件对象结构时必须保证索引事务的原子性，任何必要阶段失败都不得提交该文件的新索引。
- 修改查询逻辑时必须保持文件级去重、稳定排序、准确总数和后端分页。
- 修改界面控件时必须保留键盘操作、屏幕阅读语义、动态字号、色觉模式和高对比度支持。
- UI 尺寸、字体、颜色和相关度阈值应从集中配置读取，不应散落为重复常量。
- 新增第三方依赖前必须核对许可证，并更新开源合规文档。
- 发布与依赖配置详见 `Release-Packaging-Guide.txt`、`Dependency-Classification.md` 和 `Required-External-Dependencies.md`。
